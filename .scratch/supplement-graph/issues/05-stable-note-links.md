# 05: 在笔记和个人正文中建立稳定的节点链接

**Blocked by:** 04：创建和维护不依附原文的个人节点。

**What to build:** 用户在两种编辑入口输入双括号，通过章、节候选选定目标，保存后点击链接打开对应内容。找不到时可主动创建节点。此路径不依赖图；反向引用和图中个人连线由 06 增加。

- [x] 两种入口共用链接规则，默认笔记不额外生成节点；候选有章、节，同节重名再显示位置或摘要。
- [x] 每个引用实例独立绑定稳定目标；同一笔记中的两处同名链接可指向不同节点。
- [x] 插入普通文字、局部编辑、删除、撤销重做和刷新不交换绑定；纯文本粘贴按未绑定处理。
- [x] 找不到时由用户主动创建并链接，取消不留空节点；无法确定的文本提示选择，不自动猜测。
- [x] 代码、转义及未闭合内容不误建有效引用；自引用可导航，保留原始 HTML 不执行的规则。
- [x] 目标改名不丢身份，删除后显示失效，新建同名节点不接管旧引用；默认内容更新移除目标也不得误连。
- [x] 正文与绑定原子保存，失败保留草稿；实际浏览器完成输入、候选选择、导航及刷新，数据层覆盖引用身份边界。

规格覆盖：US15–20、29–30、34–35、37；T4、T6–7、T13。可与 03 并行，避免把编辑器工作不必要地阻塞在图渲染上。

依据：[详细规格](../spec.md)、[审查记录](../review.md)。规格中的实施建议仍是工程建议，不提升为用户已确认的技术选型。

验证：运行受影响测试、类型检查与构建，并完成本票浏览器路径；仅为存储迁移和链接身份补充数据层测试。

### 实施检查点（建议，2026-10-25）

保留一张可独立演示的编辑任务，不将解析器、存储和编辑器另拆票。以下步骤不改变原验收，也不固定绑定字段名或编辑器方案。

1. **明确一次编辑保存的单位。** 先记录引用实例如何对应文本范围、目标身份和失效名称，以及正文、绑定、读取修订怎样一起提交。当前编辑器只传 Markdown 字符串；在 01 的异步保存接口上扩展，不绕过保存确认和草稿保护。数据库层的必要扩展由本票负责，不要求 02 提前实现链接。
2. **先验证同名实例与编辑历史。** 选择同节同名但 ID 不同的 A、B，在同一正文形成两处同名链接；前插普通文字、只编辑一处、删除一处、撤销、重做、纯文本复制粘贴，再保存和刷新。逐步核对每处实际目标 ID；代码块、行内代码、转义和未闭合片段继续按原清单处理。仅重新扫描文本、按标题或出现次序配回目标，不足以证明身份保留；无法确定时按原规格保留文字并要求重新选择。
3. **完成两种真实入口。** 默认笔记自动保存、个人正文显式保存分别走通候选、键盘选择、主动创建／取消、链接导航及改名／删除／同名重建。正文和绑定一起经历失败与重试；未成功保存的绑定不得先进入持久化关联。撤销重做必须在实际 CodeMirror 中检查，数据测试不能替代。
4. **交给 06 的是已保存引用。** 记录有效／失效引用的查询方式、来源节点与来源文本、目标身份、修订及成功保存通知。06 从这里计算反向列表和个人边；本票不建立另一份可编辑边数据。

各步均须留下对应证据后才能勾原验收项。与 03／07 的文件交接见 [dispatch-plan](../dispatch-plan.md)；不新增对图实现的依赖。
