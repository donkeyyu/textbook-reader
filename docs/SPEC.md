# 课本解读 · 需求规格

状态：教材理解场景的需求基线，当前实现见 [ARCHITECTURE.md](ARCHITECTURE.md)。项目动机与价值假设见 [CONTEXT.md](CONTEXT.md)。

本文的层级：第1节及第3节的阅读逻辑表达已确认方向；第2节是为落实方向整理的内容工作标准，并非所有条目都是用户原话；第4节是信息梳理建议；第5节仅作样例对照。后续实现按任务范围选择验收，不将样例偏好或建议提升为已确认需求。

## 1. 目标和范围

### S1 核心目标

帮助初中数学学习者在教材阅读中回答三个问题：

- 这里讲的概念或结论是什么意思？
- 为什么这样推导或变换，什么时候可以这样做？
- 当前内容与此前、此后的哪些知识有关，去哪里回顾？

学生可以独立查阅。当前场景不以判断某位学生的错误原因作为提供内容的前提。

### S2 内容范围

已确认：按教材内容的学习作用分类，用于决定补充说明的重点。学习作用包括：引出问题、定义概念、陈述性质或结论、推导或证明、示范方法、练习、探究、回顾与整理。按具体语句或步骤识别，同一片段可兼具多种学习作用。术语含义见 [GLOSSARY.md](../GLOSSARY.md)。

下表列出的是内容对象。一般段落按 C2 取舍；每道题目的基本说明按 C5 全量覆盖。

| 对象 | 提供的内容 | 所要支持的行为 |
| --- | --- | --- |
| 段落与定义 | 关键语句含义、条件、边界及必要的例子 | 准确理解教材表达 |
| 知识点 | 与前置知识、推导依据、其他方法或后续应用的关系 | 在教材中建立联系 |
| 例题步骤 | 上一步为何能到下一步、变换目的及适用条件 | 理解方法而非只跟算 |
| 课后习题 | 对应知识、教材方法与思路的说明、回顾入口及可选提示 | 回顾、选择方法并自主练习 |

内容对象包括段落、知识点、例题和课后习题。早期曾提出逐段添加说明的愿景；早期探索版本按 C2 选择必要且有价值的补充。首批为当前七年级上册的第一章“有理数”，使用定位 JSON 将说明放到对应原文位置；DonQ 后续授权其余五章按相同细度扩展，范围见 R9。具体位置和深度按 C2、C6 取舍。单条说明按 C6 判断质量。当前配方法样例不限定后续章节。

### S3 当前范围之外

当前场景是教材解读，不以个体作答诊断、自动批改、一对一辅导或自动代解为前提。视频、小学教材、其他学科等拓展尚未进入当前交付范围；这不表示永久排除，后续另行确定。补充节点图的首版范围见 R12。

## 2. 教材与内容规则

### C1 教材为依据

教材原页保持可辨认，附加内容与原页分层呈现。每条内容必须能对应到具体教材版本、印刷页码和段落、题号或步骤。

页面序号与印刷页码分别记录，核实后映射；不根据文件名或固定偏移猜测。原文、原文概括和补充解释应在内容来源记录中可区分。界面不必另设“课本已有”区域来重复当前可见原文。

### C2 解释增量

一条补充说明至少解释一个原位置没有充分展开的问题：含义、理由、条件、边界或联系。编写时先读原文及相邻上下文，再确定增量。

已确认：补充面向成绩一般或较差的学生，应帮助他们理解当前语句或题目，并快速找到上下文和相关知识。必要的前置知识须有简短说明或直达依据，不能只列知识名称；保留学生选择、列式、计算和验证的工作。每条说明应明确学生读后预期能多完成的具体学习动作，如判断概念归属、说明变形依据或识别方法适用条件。以此决定补什么、补到多深，再用学生表现检验效果。

**早期探索版本的取舍（已确认）**：仅提供必要且有价值的内容补充。围绕当前教材位置，先确定尚未讲清的理解问题及对应学习动作，再选择足以解决问题的说明。教材及相邻上下文已讲清时可以不补；说明足以支持预期学习动作后停止展开。例子、反例、知识关联或其他方法，仅在直接帮助解决当前理解问题时采用，不因内容相关就扩展。

上述取舍适用于一般段落及额外解释。DonQ 后续确认的逐题基本说明须按 C5 提供，不以“原文已清楚”为由跳过题目；每题的展开深度仍以足够支持理解为止。

2026-10-29，DonQ 确认解读面板的五槽位写法：标题陈述结论、气泡用一句话直接回应当前疑问、正文按理解顺序推进、方法提示默认折叠、关联 0–2 条。同次确认按内容分级取舍：需要逐句说明的条目不写满三段，多数条目用一段承接到位，原文已讲清或不构成理解阻碍的位置不单独建条目，只作为关联目标。第 88 页八条按此重写，作为逐页重写的样板。

按学习作用检查解释缺口时，可参考下表；各项按需采用，不是每类必须填满的清单。

| 学习作用 | 补充重点 |
| --- | --- |
| 引出问题 | 当前问题为何需要研究，已有知识或方法遇到什么困难 |
| 定义概念 | 关键词与条件的含义；必要时用例子或反例帮助辨认 |
| 陈述性质或结论 | 结论的含义、适用条件及必要边界 |
| 推导或证明 | 未展开的步骤依据、关键构造或推理的目的 |
| 示范方法 | 选择方法的理由、关键变换的目的和适用条件 |
| 练习 | 识别题目结构所需的知识、方法条件与回顾入口，保留学生的关键判断和推演 |
| 探究 | 观察方向、形成猜想的线索和验证要求，保留学生的探索过程 |
| 回顾与整理 | 已学知识之间的联系，以及容易混淆的方法条件 |

优先解释：

- **为什么**：这一步服务于什么目标，依据是什么。
- **什么时候**：使用条件是什么，哪些情况下无需这一步。
- **与什么有关**：借助哪条定义、性质或方法理解当前内容。

避免无增量地重复教材已有计算；若运算背后的依据、适用条件或常见误解确有解释价值，可以围绕它补充。当前样例移除“同除以2”的决定，不构成所有内容都禁止解释运算的规则。确有必要补充的公式，应服务于理由说明，而不是把当前例题解答再抄一遍。补充例子明确作为解释用例，不能冒充教材原例。

### C3 数学条件与表达

核对定义、等价变形条件、符号、取值范围和例外。常见错误作为一般性提醒，不能表述成已经发现该学生犯错。

区分“常用步骤”“充分条件”和“必须条件”，避免将方便做法写成唯一做法。

内容长度按问题需要控制；说明可按需展开，信息层次由具体内容决定，不要求每条内容都具备固定的提示加全文结构。

2026-10-29，DonQ 确认正文与气泡预览中的公式、数学符号用 LaTeX 编写（行内 `$…$`，行间 `$$…$$`），由 MathJax 渲染；标题保持纯文本，它同时用作搜索、图谱标签与校订比对。汉字写出的数量关系（长×宽、平均数=总量÷份数）整段保持纯文字，不把其中的运算符拆成单独公式。公式字符本身仍必须进公式：汉字关系里的希腊字母、度数、上下标各自写成公式（圆面积=$\pi$×半径×半径、每份角度=$360^\circ$÷$n$），不留在正文的字体里。单位用正体（`$5\ \mathrm{m}$`、`$2.5\ \mathrm{kg}$`），数值与单一字母单位之间留空格，否则该字母按变量读。

### C4 知识关联

每个关联包含来源位置、目标位置、关系说明和阅读目的。关系可包括前置定义、变换依据、另一种方法、后续应用。说明当前为什么需要查看目标，再提供入口。既支持向前回顾定义与依据，也支持向后查看其他解法和后续联系；关联不等于只推荐前置知识。

优先指向教材中真正相关的内容，区分“本页已使用的依据”和“后续将学的方法”。未核实的出处不展示为精确页码链接。目标不存在时明确提示，保留当前阅读位置。

### C5 习题回顾引导

2026-10-23，DonQ 确认当前七年级上册每道题都要提供：考查的知识点、思路与方法、需要注意的条件或情况，以及可回到教材查看的相关知识。覆盖例题、练习、习题、复习题和明确要求作答的思考、探究、活动。

先对原页建立逐题清单，再核对说明覆盖，不能以已有解读条目作为题目全集。每个独立题号有对应入口；同题连续小问可以共用入口，但须逐一涵盖，不同方法或条件须标明适用小问。跨页题核对完整上下文并按一题记录。无题号的问题使用可核对的标题或原句定位。入口对应题号或题干，原有步骤解读可继续保留。

每题明确说明知识如何用于当前题目、应识别的结构或可采用的方法，以及符号、范围、单位、特殊值等实际相关的注意事项，不用泛化模板凑项。相关知识至少提供一个已核对的教材位置，并说明查看目的。逐题覆盖记录保留题号、小问、PDF 页序与对应说明，未完整核对前不标为已覆盖。

习题内容以题号为入口，提供教材中的相关知识、方法与思路，并说明这些方法与本题结构如何相关。可以用简短说明、教材回顾入口或启发性问题帮助学生识别结构、检查条件和选择方法，不必全部写成反问。保留学生把方法应用到本题的推演工作。

审核时逐句判断：提示是在帮助学生作出判断，还是已经替学生选定全部步骤、完成关键变形或给出答案。后者不作为习题回顾引导，折叠展示也不改变此边界。是否另设答案区尚未决定。

例如，“使用一半的平方前，需要确认哪个系数？”属于方法条件回顾；“本题先除以2，再加9/16，最后……”已接近代替完成本题，应避免作为默认习题提示。

### C6 内容验收

每条拟采用内容都应通过以下检查：

1. 教材位置和来源已核实，补充内容可与原文区分。
2. 可用一句话说明它增加了什么理解，对应的预期学习动作明确；早期探索版本还应符合 C2 的内容取舍，避免重复原文或过度拓展。
3. 数学条件和例外准确，未把方便做法写成唯一做法。
4. 关联目标确实能支持当前问题，页码与关系说明一致。
5. 习题提示保留学生的关键判断和推演。
6. 题目说明满足 C5 的四项要求，逐题清单与原图、题目入口相符，未遗漏小问。

记录未通过项，修订后再作为已审核内容交付。内容正确并不等于已证明教学效果，效果评估见 CONTEXT.md。

## 3. 阅读逻辑需求

### R1 从教材位置进入

以真实教材内容为阅读底版，补充解读依附对应段落、知识点、例题步骤或习题。学生能从正在阅读的位置找到说明，并能辨认哪些内容属于补充。定位在支持的页面尺寸下保持准确，正文保持可读。

### R2 按需查看解读

学生能够查看与当前位置相关的解释及知识关联，再继续阅读教材。解读标题行提供“定位”，滚动离开后可回到当前解读对应的原文；保留已展开的方法、关联返回记录、面板阅读位置和未保存笔记。分组入口选择条目后定位该条目，个人补充也可定位。DonQ 确认：解读从当前教材位置展开，标题和正文不重复标注当前位置的“印刷第 X 页”等页码标签，保留题号与主题；相关知识入口可保留目标页码以支持跳转。短提示、完整说明的具体组织可以根据内容需要选择；原型中的气泡和右侧区域是这一逻辑的一种表达，不是所有内容的固定格式。

### R3 关联查阅与返回

选择关联知识后，到达相应教材位置，保留返回原阅读位置的方式。返回后应能继续此前的阅读任务，不必重新寻找来源步骤。关联目标缺失时明确提示，保留来源上下文。

解读位于教材下方时，顶部中央提供可拖动的高度调整把手。调整过程中保留原文阅读位置和未保存笔记；支持触屏及键盘调整。

### R4 续读与方法按需展开

2026-10-25，DonQ 授权执行预习复习任务中的续读与方法按需展开方案。本节承接该任务已采用的行为；具体记录格式与状态实现由源码维护。

- 首次打开某本教材从封面开始；已有有效记录时，打开该教材恢复同一版本的文件页序与页内相对位置，适应窗口尺寸变化。首次进入应用与首次打开教材分别按 R13 和本条处理。记录损坏、版本不匹配或页序无效时可正常从封面阅读；读写失败提示原因且不损坏个人内容，初始化不得先用封面覆盖已有记录。
- 跨刷新只恢复原页阅读位置，不恢复关联历史、解读面板、筛选状态、方法展开状态或未保存草稿。已保存的笔记与个人补充独立保留。
- 首次打开题目引导时，“思路与方法”默认收起；知识、注意事项、相关知识及必要说明仍可读。方法开合保留原页位置与草稿；关联返回恢复来源方法状态，直接重新打开入口则重置。默认标题与预览不搬入整套方法，内容边界仍按 C5。

DonQ 后续确认，知识、方法和注意事项是内容覆盖项，展示时不强制拆成对应模块。围绕同一个理解问题的解释可按理解顺序连续展示，必要解释直接可读；练习中供学生应用的方法提示仍按需展开。第一章“增长−2%”旁问采用“增长率与百分数→减少为何记为负数→正负号含义”的顺序；其余章节按各自理解缺口组织。

会话内的关联返回按 R3、R10 保留阅读上下文；当前多层返回属于实现选择。浏览器前进／后退整合及进一步终端适配仍未确定，不从参考原型推定。

### R5 实现质量建议

后续选定终端后，检查文字和控制的可读性、页面边界避让，以及该终端的输入方式。键盘、触屏和焦点处理按实际支持范围验证；这些是实现质量建议，不代表目前已决定支持所有终端。

### R6 阅读逻辑验收

| 检查 | 完成条件 |
| --- | --- |
| 定位 | 从教材位置进入的是对应解读；支持的页面尺寸下定位仍正确 |
| 阅读 | 解读可按需查看，学生能继续阅读原教材 |
| 来源 | 补充内容与教材可区分，解释增量符合 C6 |
| 关联 | 目标和关系说明支持当前理解；前置知识与后续联系均可表达 |
| 跳转 | 关联入口到达核实过的教材位置；目标缺失时保留来源 |
| 返回 | 能回到原阅读位置继续任务，无需重新寻找来源步骤 |

以上是阅读逻辑的验收条件。具体界面如沿用样例，再检查第5节的样例交互偏好；正式实现的支持范围与细节须在任务中明确。

# 相反数与数轴上的对称

我想理解：为什么只有符号不同的两个数叫作互为相反数？

> [!explanation] 从数轴理解
> $3$ 和 $-3$ 到原点的距离相等，位于原点两侧。
> 它们对应的点关于原点对称。

> [!hint]- 再想一步
> $0$ 的相反数是什么？它在数轴上对应哪个点？

## 我的理解

找一个数的相反数，可以想象把它对应的点沿原点翻到另一侧。
原点翻过去仍是原点，所以 $0$ 的相反数还是 $0$。

## 相关笔记

- [[数轴]]：回顾原点、正方向和单位长度。
- [[绝对值]]：比较“到原点的距离”与“所在方向”。

| 文件名、路径、扩展名、大小、操作系统创建与修改时间 | 从文件系统读取，必要时缓存 | 不重复写入 Markdown，不替代笔记内置时间 |
| AI 初始版本正文与其来源 ID、版本 | 云端初始版本备份 | 与学生笔记备份区分；本地编辑不覆盖初始版本 |

`_textbook.ai_source` 使用 `source_id` 和 `version` 两个非空字符串字段，二者共同指向云端的一份确定初始内容。来源 ID 不使用本地路径或显示标题，版本不使用会随发布变化的“最新”指代。同一来源 ID 与版本的组合应始终对应同一份内容；本地改名、移动或修改正文不改变引用。没有 AI 来源时省略整个对象，不伪造来源；来源缺失、格式错误或远端不可用时保留本地笔记，不自动替换内容。云端标识的分配与查询接口留待实施设计。

笔记库的实际磁盘位置由用户选择，具体目录布局见下文 Electron 桌面方案；不写死开发者路径，不使用 Obsidian 的 `.obsidian` 目录。教材级持久资料不能因清理缓存而删除。

界面默认不展示 `_textbook` 原始对象；anchors 显示为顶部“笔记位置”。“笔记信息”可只读查看 ID 和已知时间。YAML 源码显示完整文件头，默认折叠 `_textbook`；用户仍可展开或用外部编辑器修改。隐藏只影响展示，不是访问控制。异常 ID 或 YAML 保留原文件并提示，不静默重建身份。

#### 时间维护与外部文件变更（2026-11-01 确认）

内置时间表示笔记内容的时间，与操作系统文件时间分开；缺失字段表示未知，不用扫描或导入时间冒充历史时间。

| 情况 | `create_time` | `update_time` |
| --- | --- | --- |
| 应用新建笔记 | 首次成功保存时间 | 与创建时间相同 |
| 应用修改正文、用户属性或 anchors | 保持不变 | 成功保存修改时更新 |
| 打开、预览、切换模式、重建索引 | 不变 | 不变 |
| 仅改名或移动路径 | 不变 | 不变 |
| 手动文件已有合法时间 | 保留 | 保留，之后由应用保存内容修改时更新 |
| 手动文件缺少时间 | 保持缺失 | 首次由应用成功保存内容修改时填写 |
| 外部编辑 | 不自动修改 | 保留文件值，不用扫描时间覆盖 |

- 读取与扫描不触发文件写入。缺失 ID 在首次由应用保存或明确纳入管理时生成；仅补齐身份信息不代表内容更新，不据此补造笔记时间。
- 文件系统修改时间可独立显示为“文件修改时间”；内置更新时间可能未覆盖外部修改，不将二者混为一个值。保存失败不推进已保存时间。
- 编辑期间磁盘文件发生变化时，保留草稿与磁盘版本并提示冲突，不直接覆盖。冲突操作按下文首版保存规则执行，首版不自动合并。
- 用户自定义时间字段与内置时间独立；内置时间格式异常时保留值并提示，具体修复操作待定。

#### 路径链接与笔记身份（2026-11-01 确认）

采用可读路径链接。唯一名称可写 `[[相反数]]`；重名时使用笔记库根目录下的路径，如 `[[七年级/相反数|相反数]]`。显示名与目标路径分开，链接不额外持久绑定目标 ID。

| 情况 | 解析与处理 |
| --- | --- |
| 带路径链接 | 按笔记库根目录下的完整路径解析 |
| 仅名称且只有一个匹配 | 解析到该笔记 |
| 仅名称且存在多个匹配 | 标为歧义，提供教材、章节、页码与区域预览辅助选择，不猜选 |
| 用户选择重名候选 | 写入明确路径，可保留简短显示名 |
| 目标不存在或删除 | 显示未找到，由用户修复或创建，不自动新建 |
| 应用内改名或移动 | 更新所有能确定指向该文件的链接，保留显示别名；受影响笔记的链接文本变更按内容修改维护时间 |
| 外部改名或移动 | 若旧索引身份与新文件的唯一 ID 对应，可识别同一笔记并提示修复引用，不在扫描时自动改写文件 |
| 无旧索引且原路径失效 | 保留失效链接供修复，不按相似名称猜测；不保证跨外部改名恢复全部链接 |

稳定 ID 用于识别笔记，不意味着路径链接能在丢失历史索引后自动恢复。复制文件造成重复 ID 时标记冲突，不任意选一个；由用户指定副本为新笔记并生成新 ID。应用内复制笔记直接生成新 ID，时间按应用新建规则处理；保留 AI 来源引用不表示副本与原笔记共享身份。

#### Electron 桌面方案与首版范围（2026-11-01 确认）

采用 Electron 作为桌面容器，复用现有 React/Vite 前端，继续使用现有阅读器、CodeMirror、属性编辑和知识图能力。本轮只确认规格，不安装桌面依赖、不修改源码、不迁移用户数据。

| 部分 | 职责 |
| --- | --- |
| React 渲染界面 | 教材阅读、统一笔记与三种编辑模式、属性和定位编辑、知识图 |
| Electron 主进程 | 选择笔记库、文件读取和保存、改名移动、外部变化检测与索引管理 |
| preload 接口 | 通过少量明确操作连接前端与主进程，不暴露任意文件读写或通用 IPC 调用 |
| 本地笔记库 | 保存 Markdown、教材级持久资料与库配置 |
| 云端 | 保留 AI 初始版本备份；远程同步和恢复后续增加 |

主进程校验请求来源与路径，只允许笔记库文件操作访问用户选定的库范围；应用自身的配置与缓存使用独立内部接口管理。渲染界面开启上下文隔离和沙箱，关闭 Node.js 集成，Markdown 中的原始 HTML 不执行。安装包使用打包的前端资源；Electron 具体版本、打包工具与发布流程在实施时确定。

笔记库采用以下布局；示例中的笔记文件夹由学生自由组织，文件夹不决定教材归属，anchors 才记录归属：

```text
用户选择的笔记库/
├── 七年级/
│   ├── 相反数.md
│   └── 有理数.md
├── 复习专题/
│   └── 数轴.md
└── .textbook/
    ├── settings.json
    └── textbooks/
        └── <教材版本ID>/
            ├── catalog.json
            └── custom.json
```

- `.md` 使用已确认的 UTF-8 Markdown 与 YAML frontmatter；一篇笔记可关联多本教材，无需因归属不同复制文件。
- `.textbook/settings.json` 保存属性类型、显示与隐藏规则及编辑偏好；具体字段模式仍待定。
- `catalog.json` 保存 PDF 索引目录与文件页序、印刷页码的核对映射；`custom.json` 保存同教材内复用的自定义章、节。两者均采用 JSON，具体字段在实施时确定，目录更新规则按下文执行，更新原始目录不覆盖学生条目。
- `.textbook` 是持久资料，随笔记库备份；普通笔记检索不将其中 JSON 当作笔记正文。章、节通过稳定标识引用，显示名称变化不要求改写所有笔记。
- 上次打开的笔记库位置、窗口布局、光标与滚动位置放在笔记库外的本机应用数据目录，按库隔离。它们不是笔记正文或用户共享配置，具体状态文件名待定；不要求将未保存草稿视为已保存内容恢复。
- 首版扫描文件并在内存建立索引，文件变化后更新受影响条目；不把 SQLite、IndexedDB 或其他持久缓存数据库作为首版前提。后续若增加持久索引，放在笔记库外的本机缓存目录。缺少历史路径索引时按既定规则保留失效链接，不承诺识别应用关闭期间的所有外部改名。
- 未来 Git 可管理 Markdown 和 `.textbook` 持久文件，缓存、临时文件与本机窗口状态不进入版本管理；本轮不增加 Git 操作。

保存时记录读取版本的内容摘要，写入前检查磁盘是否变化；发现冲突则保留草稿与磁盘版本，不直接覆盖。文件变化通知只触发重新读取和索引更新，不自动修改 Markdown。保存单个属性时尽量保留其他 YAML 字段、注释和顺序。检查与写入之间仍可能有外部修改，不能以一次预检查宣称完全避免冲突；具体可恢复写入流程与失败处理在实施设计中落实。

首版桌面交付范围：

- 一次打开一个用户选择的本地笔记库，读取手动创建的文件，创建、编辑和保存 Markdown。
- 复用教材阅读与统一笔记界面，支持顶部属性、anchors 编辑及正文三模式、文件头两种展示。
- 支持路径链接、重名选择、应用内改名与移动，以及外部文件变化和编辑冲突处理。
- 正常保存后关闭、重新打开应用，可恢复笔记库及已保存内容；恢复可用的阅读与编辑位置，位置无效时仍可打开内容，不从缓存伪造保存成功。
- 云端保留 AI 初始版本，本地导入时保留来源 ID 与版本；首版不迁移旧个人内容，不实现学生笔记云端备份。

首版不增加 Git 集成、远程同步与恢复、插件系统、多窗口、自定义目录批量更新或聚类界面。2026-11-01 确认以 macOS 开发验证，同时支持 Windows，两端均须验收；既有网页版保留现状，新本地笔记能力先仅在桌面交付。首版只支持当前教材，首次下载完成后可离线阅读，不增加个人 PDF 上传。安装包签名与分发方式须在对外发布前确定，自动更新延后。

#### 首版内容、保存与兼容规则（2026-11-01 确认）

以下承接已确认的 P0、P1 方案，本轮只更新规格，不开始实现。

**教材获取与统一内容**

- 用户明确添加教材时，下载该版本所需教材资源，并导入目录与初始笔记包；正常阅读或后台扫描不自动生成大量笔记文件。首次完整下载成功后，教材原页与已导入的笔记可离线打开、阅读和编辑，所需字体、公式渲染等资源不得依赖在线请求。
- 下载未完成、校验失败或缺少资源时不标为离线可用，保留已保存笔记并提供重试；重复导入不覆盖已有笔记。资源存储路径、下载清单及校验实现由实施设计确定，教材资源不混入可随意清理的索引缓存。
- 一篇 Markdown 对应一个知识图节点，多个 anchors 不产生多个节点。教材标记、搜索和知识图打开同一篇笔记；手动文件尚无 ID 时也可读取，不因生成图谱而自动写入 ID。
- 既有默认关联两端都有笔记时转换为正文链接，保留关系说明与阅读目的。只有教材位置的目标继续提供原文跳转，不为了连线生成空白笔记；原文跳转的具体序列化方式在转换模块实施前确定。
- 不自动迁移旧云端个人内容，旧系统内容保持可用；默认内容的初始笔记包转换不等同个人内容迁移。学生笔记云端备份延后，AI 初始版本继续独立保留。

**保存、模式与无效文件**

- 有效内容自动保存，支持快捷键立即保存；显示未保存、保存中、已保存及失败状态，不以界面内容变化代替写入成功。自动保存的等待时长为实施参数。
- 外部文件变化且存在编辑草稿时暂停自动保存，保留双方版本，提供查看差异、另存草稿与采用磁盘版本。采用磁盘版本前保护尚未保存的草稿；首版不自动合并。
- YAML 暂时无效时保留源码草稿，暂停自动保存与属性可视化写入，指出错误位置；不得通过重建文件头丢弃未知内容。“按原样保存”是否开放及其具体操作仍待确定，不作为首版必需能力。
- 默认实时预览与属性预览，模式偏好按笔记库保存。只读预览显示属性和位置，不提供修改控件。
- 首版 callout 支持理解、提示、注意、个人补充，保留折叠语法；未知类型仍显示标题和正文。具体类型标识及旧内容转换规则在编辑模块实施前确定，不要求完整兼容 Obsidian。
- 未知字段原样保留。遇到高于当前支持的格式版本时只读打开，避免旧应用覆盖新格式。异常 ID 或 YAML 不静默改写；异常时间保留并提示，不自动纠正设备时钟或捏造历史时间，正常保存遵循已确认的时间维护规则。

**身份、目录与链接边界**

- 新笔记采用 UUID，现有合法 ID 保留。重复 ID 按既定冲突规则处理。同目录创建重名文件时建议“名称（2）”等可用名称；改名遇到已有文件时阻止覆盖，跨目录允许重名。
- anchors 使用“教材 → 章 → 节”和“教材 → 页面 → rects”两条依赖链。有效页面不依赖章、节填写；只有章节时可归类。章、节与页面冲突时提示且不自动修改；无效字段保留，不用于定位。手动输入越界坐标或失效标识的具体提示方式在实施时确定。
- 同一父级下自定义目录重名时提示复用，改名保持 ID。删除被引用条目前显示引用数量，要求选择替代项或明确移除归属；批量修改功能仍不纳入首版。
- 更新教材目录不按数组顺序重新生成 ID。旧条目消失时保留失效引用并提示修复，不猜测新目标，不覆盖自定义条目。
- 同一笔记库内同名用户属性共用显示类型；配置不强制转换文件值，类型不符时提示。
- 首版链接支持笔记路径与显示别名；标题、块级链接保留原文，不视为已支持的跳转。应用创建链接使用统一的库内路径规范，具体大小写、转义和扩展名约定在链接模块实施前固定。
- 应用改名或移动前，列出可确定的引用；逐文件检查外部变化，部分改写失败时显示未完成清单并允许重试，不报告全部成功。具体可恢复写入与操作记录机制由实施设计确定。
- 路径链接指向同一路径后来创建的新文件时，没有历史证据就无法判断它是否仍为原目标。首版接受此限制，不增加持久目标 ID 绑定；有证据的身份冲突仍须提示。

桌面验收补充：macOS 与 Windows 均检查选库、读取、保存、重开、链接改名和外部编辑冲突；下载完成后断网并重启，验证教材阅读、已导入笔记编辑、公式及关联导航；失败或部分下载不能伪报完成。选库取消不破坏内容，重复导入不覆盖已有笔记，一篇文件对应一个节点；自动保存、无效 YAML、外部冲突、较新格式只读、重名及部分引用改写失败均按上述规则处理。文件操作不能越出所选库，清理索引缓存不删除笔记、教材目录、自定义条目或离线教材资源。不以开发环境启动成功代替桌面交付验收。

## 5. 配方法参考样例

本节仅用于对齐内容逻辑，文案可按内容标准改进。教材来源见 CONTEXT.md。

### E1 教材上下文

九年级上册“21.2.1 配方法”，例1（2）的题目是 `2x² + 1 = 3x`。题目与分析见印刷第7页，解答在第8页。

解答依次包含移项、二次项系数化为1、配方、开平方与求根。这里只记录识别依据，不要求在补充面板重复这些步骤。

### E2 “二次项系数化为1”的解释重点

- 为什么：便于直接使用 `x² + bx + (b/2)² = (x + b/2)²`。这里的一半规则对应二次项系数为1的形式。
- 什么时候：选择配方法，系数不为1，又不容易直接看出平方结构时，可先化为1，以统一形式配方。
- 什么时候不必：系数已经为1，或者能直接识别或配成平方。例如补充用例 `4x² + 4x + 1 = (2x + 1)²`。
- 回顾入口：第7页配方流程，解释从完全平方公式倒推缺项的关系；不把它描述成完全平方公式首次出现的页码。

该位置的气泡可概括为：“为了方便配成完全平方，并非每题都必须这样做。”完整说明再解释条件。两边同除以2以及变换后的系数、常数已由教材展示，不作为此处解读重点。

### E3 其他步骤如何补充

配方步骤解释“一半”来自公式中的交叉项，以及补出平方与保持等式成立分别解决什么问题。开平方步骤解释把括号内看成整体，以及平方等于正数、0、负数时，在实数范围内的不同情况。

习题引导可回到“二次项系数是否为1”“是否已经能看到平方结构”等判断，而不直接列出某题的全部运算。具体习题题号和提示须核对教材后再补充，本文不虚构已完成的习题覆盖。
