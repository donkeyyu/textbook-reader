## 当前源码与公开契约

`content-store.ts` 从 Supabase 读取默认内容；`content.ts` 提供稳定身份、全部节点和基于同一默认快照的位置查询；静态教材位置与页图继续复用。`cloud-personal.ts` 管账号／教材快照、迁移和修订保存，`useBookContent.ts` 管 React 载入、保存队列、身份代次及通知。`personal.ts` 保留旧数据格式及旧 localStorage 读写，不再作为新阅读器的保存入口。

实际字段与调用约束统一记录在 [02 的下游公开契约](issues/02-local-content-migration.md#下游公开契约)。下游注意：

- 全图消费 `nodes`／`contentNodes`，包含隐藏和未连线的全部条目；默认查询 `supplementsForLocation` 返回该位置的全部补充。
- 节点身份为教材、来源和原 ID 的组合，不能按标题、印刷页码或坐标重新绑定。
- 当前个人修订按账号和教材的一份快照计算。保存必须使用读取时的快照；外部变更提示不自动推进编辑基线。
- 04 已支持无原文位置的自由节点；框选节点仍保留完整页序和区域。05 的可选 `noteBindings`／`bindings` 与正文同次保存，继续沿用 01 的草稿保护。
- 06 从已保存快照和当前同册节点投影反向来源与个人边；默认关联独立保留，不另存可编辑关系。07 的视图与宽度只在会话中保留，教材续读沿用原记录，图布局不持久化。
- 同源标签通知与跨设备重新读取不同，不将当前通知解释为跨设备实时同步。
