# 08: 路径链接、重名选择与反向引用

Status: ready-for-agent
Category: enhancement

**What to build:** 用户通过双括号链接本地笔记，选择同名候选后得到明确路径，并可导航和查看反向引用。

**Blocked by:** 05：正文三模式与文件头独立切换

## Acceptance criteria

- [x] 实施前固定库内路径的大小写、扩展名和转义约定，覆盖 macOS、Windows；路径不能越过笔记库。
- [x] 唯一名称可解析，多个同名目标标为歧义，不按章节相近或旧绑定猜选；候选显示现有教材、章节、页码、区域预览或可用摘要，缺失信息不伪造。
- [x] 选择同名候选写入明确库内路径并可保留显示别名；不额外保存旧式目标 ID 绑定作为链接依据。
- [x] 缺失目标显示未找到，由用户选择修复或创建；创建按 UUID 与重名保护规则执行，不因扫描自动创建文件。
- [x] 已解析链接可打开目标并返回来源编辑现场；正文和用户属性值中的合法笔记链接均参与解析与反向引用，反向引用从持久内容重建，重复引用、移除引用和未保存草稿处理一致。
- [x] 代码、转义文本等非链接语法不产生错误引用；标题与块级链接保留原文且不伪报支持。
- [x] 缺少 ID 的手动笔记也可通过路径访问和索引，解析不修改文件；路径被新文件复用且无历史证据时不声称识别原身份。
- [x] 反向引用和搜索索引可重建，不删除笔记；无联网条件也能解析本地链接。

- 转义协议：目标及别名中的 `\[ \] \| \# \^ \\` 表示字面字符；仅别名可含文件系统禁止的 `|`。路径不做 URL 解码，`%` 是字面字符；未转义的 `#`、`^` 属不支持的标题/块语法，保留原文而不建立关系。拒绝绝对路径、反斜线分隔、`.`/`..`、隐藏段、Windows 保留名/字符、控制字符及段尾空格/点。路径中的空格保留；应用生成时统一转义语法字符。文件名边界复用当前 Vault 规则。
- 索引与编辑协议：正文按 Markdown 语法排除代码、转义、HTML 与普通链接；顶层用户属性的字符串值（含列表/对象内值）参与，保留对象和属性名不参与。反向引用只使用磁盘扫描内容，重复引用按来源笔记合并。草稿可导航但不进入持久索引；返回保留来源草稿、模式、光标和撤销现场，外部变化继续走冲突保护。缺失目标需明确点击创建；创建沿用现有 UUID、重名保护和父目录须存在规则。09 可复用本票的提取、解析及引用替换接口，08 不实现改名移动。
