# 02: 原有教材与个人内容迁入本地数据库后继续阅读编辑

**Blocked by:** 01：保存完成后才确认笔记已保存。

**What to build:** 读者升级后仍能阅读完整教材、打开原有补充、编辑已有笔记和个人补充；刷新后读取本地数据库中的同一批内容。默认内容与个人内容迁移都在这一条可验证路径中完成。

- [ ] 默认节点保留教材身份、稳定 ID、类型、完整正文和教材位置；默认正文只读。
- [ ] 默认内容可重复导入与按修订更新，个人内容不被覆盖；阅读查询使用新的同一节点数据源。
- [ ] 旧个人节点 ID、标题、Markdown、页序、区域和节点笔记迁移完整；章节可核实则映射，否则未归属。
- [ ] 迁移事务失败不标完成、不删原数据；重试不重复，也不覆盖数据库中已经更新的个人记录。
- [ ] 记录并实现旧版本标签的存储切换保护：阻止旧写入并保全草稿，或检测并保全迁移后的旧存储写入；不得凭迁移完成标志忽略后到内容。冲突保全两边内容并提示，不以重新导入覆盖新库；写入隔离须针对现有旧代码验证。
- [ ] 存储失败、空间不足和跨标签冲突保留原数据与草稿；不主动上传个人内容。
- [ ] 用真实浏览器数据库验证首次升级、重复启动、中断重试、刷新以及旧标签写入冲突；默认内容更新也不丢个人内容。
- [ ] 在独立测试 origin 下，用同 origin 的旧版、新版页面走通“旧页保持打开 → 新页迁移 → 旧页保存 → 刷新”，验证保存明确受阻且草稿可保全，或后到内容被检测并保全；再验证新旧两边修改同一记录不会覆盖新库，冲突内容均保留并提示。两个新版标签不能代替此混合版本验收。

规格覆盖：US31–36；T9、T10。推荐 IndexedDB，最终选择记录在任务交付中；不建设服务端或通用仓储。

依据：[详细规格](../spec.md)、[审查记录](../review.md)。规格中的实施建议仍是工程建议，不提升为用户已确认的技术选型。

验证：运行受影响测试、类型检查与构建，并完成本票浏览器路径；仅为存储迁移和链接身份补充数据层测试。
